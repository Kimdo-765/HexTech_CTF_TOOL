- **Codex 처방 (채택)**: generic scan에서 `finditer()`로 span/context를 보존하고,
  match 바로 뒤가 `]`+수량자+`}` 인 **정규식 소스 모양일 때만** 신뢰도를 낮춘다.

### A7. 취소된 job의 에이전트 자식이 회수되지 않는다  ★ 양방향 검증 완료

- **메커니즘 (Codex가 코드 실행으로 재현)**: `modules/codex_cli.py:490-502`가
  `start_new_session=True`로 자식을 띄운다. `receive_response()` **취소**는
  `except asyncio.TimeoutError` 분기가 아니므로 `_stop_process()`를 부르지 않고,
  `finally`가 `self._proc = None`으로 핸들을 버린다(`:712-728`).
  그 뒤 `close()` → `_stop_process()`는 `proc is None`에서 **즉시 반환**한다(`:776-779`).
  stop 라우트는 RQ job 취소와 sibling 컨테이너 회수만 하고(`api/routes/jobs.py:188-264`),
  analyzer의 finally cleanup은 agent CLI를 **의도적으로 제외**한다(`_common.py:7577-7646`).

- **Claude 독립 재현 — 목이 아니라 실제 프로세스로**:

  ```
  취소 경로   자식 pid=1067190  close() 후 생존=True   ← 누수 (ppid 재지정됨)
  대조군      timeout 경로      close() 후 생존=False  ← 회수됨
  ```

- **라이브 귀속 (Claude 확인 — Codex는 namespace 제약으로 UNVERIFIABLE이었다)**:

  ```
  rq:job:d5e018600139  status='stopped'  ended_at=''  last_heartbeat='2026-08-13T13:07:15Z'  worker_name=''
  rq:job:c09f2a6c48ff  status='stopped'  ended_at=''  last_heartbeat='2026-08-14T12:00:50Z'  worker_name=''
  rq:worker:htct-s1-w0  state='idle'  current_job=''   heartbeat 방금 갱신
  rq:worker:htct-s2-w0  state='idle'  current_job=''   heartbeat 방금 갱신

  worker-1 내부   pid=1205   ppid=1  etime=1-02:55:35  job=d5e018600139
                  pid=76600  ppid=1  etime=02:53:50    job=c09f2a6c48ff
  호스트          sid = 자기 자신 (start_new_session=True 의 세션 리더)
  ```

  **`ppid=1`이 고아 signature다** — 부모(RQ work horse)가 사라져 init이 입양했다.
  RQ는 stopped, 워커 둘 다 idle인데 자식은 하루 넘게 살아 있다.
- **수정**: 회수 책임은 broad `pkill`이 아니라 자식을 만든 `CodexCLIClient`에 있다.
  cancellation/`BaseException`에서도 process group을 종료한 **뒤에만** 핸들을 지울 것.
- **회귀 테스트**: 기존 `test_codex_cli.py` 34/0 과 `test_orphan_resource_leak.py` 16/0 은
  **취소 축이 없다.** 취소 시 자식 회수를 이름 있는 회귀로 고정할 것.
- 아무 프로세스도 죽이지 않았다 — 회수 시점은 운영자 판단.

### A9. `misc`의 `raw` 경로는 no-run 게이트 밖이다  ※ 신규 (I1b 검수 중 발견, 백로그)

- **위치**: `modules/misc/orchestrator.py:379` — `flags = sorted(set(raw + scanned))`.
  `raw = candidates + embedded` 이고 `_is_placeholder_flag` 만 통과한다.
  `scanned` 만 A0 게이트(`sandbox_started`/`agent_error`)를 지나므로 **`raw` 는 게이트 밖**이다.
- **결과**: 크래시 + 분석기 문자열 스윕이 flag 모양을 찾음 → `flags` 비지 않음 → `finished`.
- **대조**: `forensic` 은 `raw` 병합이 없어 전부 게이트를 지난다 — 같은 위험이 없다.
- **I1b 결함으로 세지 않은 이유**: (a) I1b 가 만든 것이 아니라 선행 동작이고,
  (b) Codex 가 0614 에서 명시적으로 서술했으며,
  (c) `raw` 의 출처는 에이전트 산문이 아니라 **챌린지 파일 자체**라 misc 의 목적상
  정당할 수 있다("파일에서 flag 를 찾는다"가 misc 의 일이다).
- **남는 사실**: `_is_placeholder_flag` 는 방침상 현실적 디코이를 **의도적으로** 통과시킨다
  (수동 큐레이션). 에이전트가 크래시하면 그 후보를 검토한 주체가 아무도 없다.
- **선택지**: (a) 현행 유지 — 파일에서 찾은 flag 는 에이전트와 무관하게 유효,
  (b) 크래시 시 `raw` 의 신뢰 티어를 낮춰 `finished` 승격만 막는다.
- **결정 필요**: 운영자. ⚠ 플레이스홀더 자동 폐기는 여전히 금지.
