# 완료 job 검토 → 수정 사항 정리 (2026-08-14)

대상: 최근 완료된 job들 (web 3건, pwn/rev 다수) + 앞선 두 보고서의 1·2번 항목.
근거는 모두 job 아티팩트(run.log / events.jsonl / meta.json)와 코드 라인에서 직접 확인.

## A. 코드 수정 — 안전 (동작 축소 없음)

### A1. codex 하네스가 64 KiB 한 줄에 죽는다  ★최우선
- **위치**: `modules/codex_cli.py:494` (`asyncio.create_subprocess_exec(...)`에 `limit=` 없음),
  소비 지점 `:532` (`await self._proc.stdout.readline()`).
- **증상**: asyncio 기본 스트림 한계 64 KiB. codex가 그보다 긴 JSON 한 줄을 뱉으면
  `ValueError: Separator is not found, and chunk exceed the limit` → 세션이 그 자리에서 죽는다.
- **실제 피해**: 이틀 사이 2회 재발. `a213e7591fdf`(4턴 만에 사망), `98a0718483c9`(1턴 만에 사망).
  긴 툴 출력 한 방이면 재현되므로 앞으로도 계속 터진다.
- **수정**: `create_subprocess_exec(..., limit=<크게>)` (예: 16 MiB) + `readline()`을
  `ValueError`에서 죽지 않게 감싸 부분 읽기로 폴백.
- **크기/위험**: 한 줄 + 예외 처리. 위험 낮음. 회귀 테스트: 64 KiB 초과 한 줄을 흘리는 가짜 프로세스.

### A2. prejudge가 막는 동안 샌드박스를 한 번도 안 돌리고 $700을 태운다  ★최우선
- **위치**: 차단 판정 `modules/_runner.py:1243`,
  리다이렉트/상한 루프 `modules/_common.py:9616~9709` (`_n < 3` → BLOCKED 4회까지 진행).
- **측정값** (web 3건, 전부 동일 패턴 — BLOCKED=4 · redirect=3 · cap-stop=1 · concede=0):

  | job | 턴 | 추정 비용 | 샌드박스 실행 |
  |---|---|---|---|
  | `e34c4b63b50b` | 373 | $132.95 | 0회 |
  | `f3a67cd86353` | 406 | $252.28 | 0회 |
  | `eb18a95f4399` | 293 | $332.43 | 0회 |
  | **합계** | **1072** | **~$717.66** | **0회** |

- **원인 구조**: `flag_likelihood`가 0.02~0.08로 낮아 매번 severity=high → ship 차단.
  차단은 리다이렉트로 3회까지 되돌려지고, 4번째에야 멈춘다.
  concede 게이트(`:9658`)는 **self-defeat 이슈**를 요구하므로 web에서는 사실상 발동하지 않는다
  (실측 concede=0).
- **수정**: 상한을 낮추는 게 아니라 **조기 에스컬레이션**을 넣는다 —
  "BLOCKED 2회 연속 + 샌드박스 실행 0회"이면 자동 재시도를 멈추고 운영자에게 넘긴다.
  누적 비용/턴을 함께 stop 사유에 기록.
- **크기/위험**: `_common.py` 한 블록. 위험 낮음(멈추는 방향이라 새 비용을 만들지 않음).
  단, A3 없이는 멈춘 이유가 로그에 안 보이므로 A3와 같이 나가야 한다.

### A3. WHY_STOPPED가 서로 다른 두 상황을 똑같이 "verdict: unknown"으로 적는다
- **위치**: `modules/_common.py:6915`(파일명), `:6921`(`"no_hint"` 문구), 작성부 `:7184` / `:7233`,
  분기 `:7376`; verdict 기본값 `modules/_runner.py:1405`.
- **증상**: ① prejudge가 N회 막아 샌드박스가 아예 안 돈 경우와
  ② judge가 shadow 모드라 enforce 판정이 없는 경우가 둘 다
  "Postjudge verdict: unknown"으로 적힌다. 운영자가 로그를 파헤치기 전에는 A2를 볼 수 없다.
- **수정**: stop_kind를 분리 — `prejudge_blocked_no_run`(차단 횟수·샌드박스 0회 명시),
  `judge_shadow_no_verdict`(판정이 게이트하지 않음을 명시). 기존 `no_hint`는 유지.
- **크기/위험**: 문구 + 분기. 위험 낮음.

### A4. 집계기가 진행 중 job과 `stopped_for_resume`에서 예외로 죽는다
- **위치**: `scripts/aggregate_hardening.py:824`
  (`AggregationError: unresolved failure classification: 2b495752ce97, c09f2a6c48ff`).
- **증상**: 진행 중이거나 재개 대기 상태인 job이 하나라도 있으면 집계 전체가 실패.
  베이스라인을 다시 돌릴 때마다 손으로 제외해야 한다.
- **수정**: 두 상태를 `excluded`(사유 태그 포함)로 분류. 미분류 예외는 그대로 유지.
- **크기/위험**: 분류 함수 한 곳 + 테스트 2개. 위험 낮음.

### A5. `cost_usd`가 항상 0.0으로 기록된다
- **위치**: `modules/_common.py:3982` — `"cost_usd": float(cost_usd or 0.0)`.
- **증상**: 전 job에서 `cost_usd=0.0`인데 `cost_usd_estimate`에는 $132/$252/$332가 들어 있다.
  즉 비용 기준 분석은 estimate로만 가능하고, 실제 청구값은 소실된다.
- **수정**: `cost_usd`가 비어 있으면 0.0으로 덮어쓰지 말고 `null` 유지 + estimate를 권위값으로 명시.
  (메모리 기록: `model_usage`가 권위값, SIGKILL된 세션은 estimate만 남는다.)
- **크기/위험**: 한 줄 + 소비처 확인. 위험 낮음.

### A6. flag 후보 추출에 노이즈가 섞인다
- **증상**: 후보 목록에 `DH{[^}`(정규식 조각)와 `DH{real_flag-123}`(문서 플레이스홀더)가 올라온다.
- **수정**: 추출 단계에서 **정규식 메타문자를 포함한 후보**를 제외.
  ※ 플레이스홀더 자동 폐기는 하지 않는다 — 운영자 방침상 flag 큐레이션은 수동(🗑️/📌).
  노이즈 제거는 "정규식 조각처럼 문법적으로 flag가 될 수 없는 것"에 한정.
- **크기/위험**: 필터 한 줄. 위험 낮음(수동 큐레이션 원칙을 건드리지 않음).

## B. 운영 설정 — 코드 아님

### B1. `job_ttl_days=7`이 측정 코퍼스를 파괴한다
- **위치**: `modules/settings_io.py:52` (`("job_ttl_days","JOB_TTL_DAYS",int,7)`).
- **증상**: S1 베이스라인 20건 중 **0건이 생존**. 개선 전후의 분류 분포 비교가 설계상 불가능하다.
- **선택지**: (a) TTL을 30일로 올린다, (b) TTL은 두되 회수 전에
  `events.jsonl` / `meta.json` / `run.log`만 별도 보관 디렉터리로 승격한다.
- **권고**: (b). 디스크를 지키면서 측정 입력(append-only·타임스탬프)만 남긴다.
- **결정 필요**: TTL 값 또는 보관 정책은 운영자 판단.

## C. 운영자 결정 필요 — 게이트 정책 변경

### C1. `flag_likelihood < 0.2` 하드컷 완화 (앞선 보고서의 3번)
- **위치**: 정책 근거 주석 `modules/_runner.py:1193` (Tier 1.7), 판정 `_judge.prejudge_blocks_ship()`.
- **쟁점**: 이 컷은 실제로 낭비를 막은 이력이 있다(job `7f903a8e152b`: fl=0.02에서 사이클 낭비).
  반대로 web 3건은 이 컷 때문에 샌드박스를 **한 번도** 못 돌려 봤다.
  또한 과거 concede 판정이 틀렸던 전례가 있다(securalloc — 실제로는 풀 수 있었다).
- **정리**: A2(조기 에스컬레이션)만 넣어도 $717짜리 출혈은 멈춘다.
  컷 자체를 건드리는 건 별개 결정이므로 **승인 없이는 구현하지 않는다.**
- **선택지**: (a) 현행 유지 + A2만 적용(권고), (b) web 모듈만 컷을 0.1로 완화,
  (c) 컷을 "차단"이 아니라 "1회 실행 허용 후 재평가"로 바꾼다.
