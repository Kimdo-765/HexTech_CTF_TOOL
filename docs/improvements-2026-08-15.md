## R1 — A11: 크래시 시 러너 산출물을 신뢰하지 않는다  ★ 최우선

### 문제

`modules/_common.py:1783-1784`

```python
crashed_before_sandbox = sandbox_started is False and bool(agent_error)
if sandbox_skipped or crashed_before_sandbox or trusted_only:
```

크래시+미실행이면 narrative 를 막고 **`trusted_only` 경로**로 보낸다. 그런데
`_TRUSTED_FLAG_SOURCES` 에 `exploit.py.stdout` / `solver.py.stdout` 이 있다.
러너는 stdout 을 `work_dir` 에 쓰고(`_runner.py:1347`) `/retry` 는 `work/` 를
새 job 으로 복사하므로, **이전 시도의 stdout 을 들고 재시도 → 이번엔 샌드박스 전 크래시**
경로에서 아무도 실행하지 않은 flag 가 `tier='marker'`(최상위)로 채택된다.

### 처방 후보 3안을 같은 사례에 걸었다

```
사례                                        기대   RX-1  RX-2  RX-3
ATK  스테일 stdout + 이번 시도 크래시            차단   차단   차단   차단
CTL1 러너 실행 + artifacts 기록                통과   통과   통과   통과
CTL2 옛 job 재스캔 (artifacts 없음, 정상 실행)   통과   통과   통과   통과
CTL3 collector 콜백 (샌드박스 없음)             통과   차단✗  통과   차단✗
                                          점수   3/4   4/4   3/4
```

- **RX-1** `meta.artifacts` 에 이름이 있는 것만 신뢰 — **내 첫 직감이었고 틀렸다.**
  collector 콜백은 러너가 아니라 OOB 수신이라 `meta.artifacts` 에 없다.
  샌드박스 없이 원격 봇이 flag 를 보내는 정당한 경로를 죽인다
  (참고: 원격 봇은 지정된 COLLECTOR_URL 로만 나갈 수 있다).
- **RX-3** mtime 이 이번 시도 시작 이후인 것만 — 시도 시작 시각을 크래시 경로에서
  신뢰성 있게 얻기 어렵고, 정상 캡처(CTL1)도 같이 죽는다.
- **RX-2 (채택, 4/4)** 크래시면 **러너가 쓰는 파일(`*.stdout`/`*.stderr`)만 배제**하고
  OOB 소스(`callbacks.jsonl` 등)는 유지한다.

### 왜 RX-2 가 원리적으로 옳은가

`sandbox_started` 는 **이번 시도** 단위 값이다(False 로 초기화, 러너 호출 직전 True).
따라서 크래시 분기에서는 "러너가 이번 시도에 돌지 않았다"가 **이미 확정**돼 있고,
디스크의 러너 산출물은 정의상 스테일이다. 반면 collector 콜백은 러너 산출물이 아니므로
같은 논리가 적용되지 않는다. 파일 목록이 아니라 **누가 썼는가**로 가르는 것이 맞다.

### 요구

1. `crashed_before_sandbox` 분기에서 신뢰 소스를 **러너 산출물 제외**로 좁힌다.
   판별은 파일명 하드코딩이 아니라 "러너가 쓰는 종류"로 — 이미 `meta.artifacts` 가
   `{script, stdout, stderr}` 를 기록하므로 그 **키 종류**를 기준으로 삼을 수 있다.
2. 회귀 4개를 위 표 그대로 고정한다. **CTL3 이 음성 대조군의 핵심**이다.
3. ⚠ 같은 job 안의 다중 시도(attempt 1 이 샌드박스를 돌고 attempt 2 가 크래시)는
   RX-2 로 닫힌다 — 러너 산출물을 종류로 배제하기 때문에 시도 경계와 무관하다.

## R2 — A12: 오류 "문구"가 아니라 오류 "발생"으로 판정한다  ※ 소규모

게이트가 `bool(agent_error)` 이고 호출부 7곳이 전부 **오류 메시지 문자열**을 넘긴다.

```
agent_error=True/'boom'/1   -> 차단
agent_error=''/0/False/None -> 통과      ← 빈 메시지 크래시가 게이트를 끈다
```

`agent_error_kind` 는 메시지 내용과 무관하게 세팅되고(`_common.py:8817`),
**호출부 7곳이 이미 그 값을 읽고 있다**(`agent_err_kind = agent_summary.get(...)`).

### 요구

각 호출부에서 `agent_error=bool(agent_err) or bool(agent_err_kind)` 로 바꾼다.
대상: `pwn/analyzer.py:2537` · `rev/analyzer.py:314` · `web/analyzer.py:510` ·
`crypto/analyzer.py:339` · `web3/analyzer.py:286` · `misc/orchestrator.py:384` ·
`forensic/orchestrator.py:388`.
회귀: 빈 메시지 + kind 있음 → 차단 · 메시지도 kind 도 없음 → 통과(음성 대조군).

※ `sandbox_started is False` 의 타입 엄격성은 **의도된 설계**다(`None`=unknown 을
차단으로 접지 않기 위함). 바꾸지 말 것. 다만 경계에서 정규화하면 미래 호출자가 `0` 을
넘겨 조용히 게이트를 끄는 일을 막을 수 있다.

## R3 — A6 확장: **기각**  ※ 시험해서 물렀다

현재 `_REGEX_SOURCE_TAIL_RE = \](?:[+*?]|\{\d+(?:,\d*)?\})\}` 는 `DH{[^}]}` 와
`DH{[^}][^}]*}` 를 놓친다. 수량자를 선택으로 만드는 확장(`...)?\}`)을 시험했다.

```
노이즈  DH{[^}]}          현재 놓침 → 확장 잡음        (+1)
노이즈  DH{[^}][^}]*}     현재 놓침 → 확장도 놓침       (0)
진짜    DH{x}]}           현재 통과 → 확장이 **버림**   (-1)
        진짜를 버린 건수: 현재 0 · 확장 1
```

노이즈 1종을 더 잡는 대가로 **진짜 flag 를 새로 버린다.** 수동 큐레이션 방침에서
노이즈는 사람이 지울 수 있지만 사라진 flag 는 복구할 수 없으므로 **나쁜 거래**다.

**권고: 현행 유지.** 남은 `DH{.*}` · `DH{\w+}` · `DH{[a-z]+}` 부류는 `FLAG_RE` 에
완전 일치해 **모양만으로 진짜와 구분 불가**하며 패턴 매칭으로 풀 수 없다.

## R4 — B1 보관본 상한  ※ 운영

승격 구현 자체는 견고하다(형제 디렉터리 · 같은 디렉터리 임시파일 → `os.replace` ·
pid+tid 충돌 회피 · 실패 전건 기록 · 회수 미차단). 다만 **보관 디렉터리에 회수 정책이
전혀 없어 무한 증가**한다. 실측: `run.log` 가 294 KB 인 job 이 있다.

선택지: (a) 현행 유지하고 주기적으로 사람이 정리, (b) 보관본에 별도의 긴 TTL(예: 180일),
(c) `run.log` 만 gzip 압축(측정 입력으로는 압축본으로 충분하다).
**권고: (c) 후 (b).** 어느 쪽이든 **측정 목적에 필요한 최소 집합만 남긴다**는 원칙은 유지.
